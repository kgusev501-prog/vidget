# Vidget

Виджет-шторка для Windows 11: еле заметная полоска у верхнего края экрана, которую
можно потянуть вниз — выкатывается панель поверх всех окон с тремя вкладками.

| Вкладка | Что умеет |
|---|---|
| **Музыка** | обложка, трек и исполнитель, пуск/пауза, предыдущий/следующий, перемотка, лайк и дизлайк, громкость самого плеера, поиск трека с воспроизведением прямо в панели |
| **Буфер обмена** | история копирований — текст, ссылки, код, цвета, картинки, а также скопированные файлы и папки; поиск, закрепление, предпросмотр, возврат в буфер одним кликом |
| **YouTube** | поиск видео, воспроизведение прямо в панели живой картинкой, звук продолжается при закрытой шторке, клик по видео открывает его в браузере |
| **Заметки** | быстрая запись в одно поле (Enter — сохранить), стикеры, поиск, полноценный редактор с автосохранением |

## Как это работает

- **Окно.** Одно прозрачное окно 980×300 всегда висит поверх всех приложений
  (`always-on-top` уровня `screen-saver`), не появляется в панели задач и не
  меняет размер — ресайз прозрачного окна в Windows оставляет неперерисованные
  области. Пока шторка закрыта, окно пропускает клики насквозь; main-процесс сам
  следит за курсором и «забирает» мышь, только когда указатель над полоской.
- **Выбор проигрывателя.** Панель показывает и ведёт тот источник, который
  сейчас звучит, — Яндекс Музыку, браузер, Spotify или собственный плеер
  виджета. Поэтому вкладка называется просто «Музыка».
- **Музыка.** Управление идёт через системный SMTC
  (`GlobalSystemMediaTransportControls`) — тот же механизм, что и у медиа-клавиш.
  Работает не только с десктопным Яндекс Музыкой, но и с любым плеером,
  который публикует сессию (браузер, Spotify). Мост — долгоживущий процесс
  Windows PowerShell 5.1 ([src/ps/smtc-bridge.ps1](src/ps/smtc-bridge.ps1)),
  обменивается с приложением построчным JSON.
- **Громкость.** Виджет двигает не системный регулятор, а громкость сессии
  самого плеера в микшере Windows — то есть ровно тот уровень, который в Яндекс
  Музыке настраивается независимо от системного. Процесс находится сопоставлением
  SMTC-идентификатора приложения (`ru.yandex.desktop.music`) с путями процессов,
  у которых есть аудиосессия. Если сессию найти не удалось, ползунок управляет
  системной громкостью — что именно, написано в подсказке при наведении.
  Крутить колесо мыши можно прямо над динамиком или ползунком: шаг 5 %,
  отправка на плеер придерживается, чтобы быстрая прокрутка не выстраивала
  очередь вызовов.
- **Лайки и обложка.** SMTC про лайки ничего не знает, а десктопный Яндекс
  Музыка не публикует и миниатюру, поэтому виджет обращается к тому же API, что
  и само приложение (`api.music.yandex.net`): `likes/tracks/add`,
  `likes/tracks/{id}/remove` и то же самое для `dislikes`. Трек ищется по
  исполнителю и названию через `/search`; оттуда же берётся обложка (шаблон
  `avatars.../%%` → `400x400`). Результаты кэшируются на время работы. Дизлайк,
  как и в приложении, сразу переключает трек.
- **Поиск трека.** Строка поиска в верхней части вкладки: `Enter` — искать
  (через тот же API, что и лайки). Клик по найденному запускает трек прямо в
  панели — во встраиваемом плеере Яндекса
  (`music.yandex.ru/iframe/track/<id>/<albumId>?autoplay=1`); десктопное
  приложение при этом ставится на паузу, чтобы не играли двое сразу.

  Плеер стоит за пределами панели и виден не будет: он нужен только чтобы
  звучать. Управляют им обычные кнопки сверху — встроенный плеер регистрирует
  свою медиасессию Windows, ту же, через которую виджет управляет любым другим
  проигрывателем.

  **Почему не через десктопное приложение.** Ссылка `yandexmusic://album/<id>/track/<id>`
  открывает страницу трека в приложении, но воспроизведение не начинает —
  проверено, трек не меняется. Так что запустить выбранное можно только
  собственным плеером.

  **Важное ограничение.** Полный трек плеер отдаёт только слушателю, вошедшему в
  аккаунт, а окно виджета — отдельная браузерная сессия, и входа в ней нет.
  OAuth-токен, которым работают лайки и поиск, к веб-плееру отношения не имеет.
  Поэтому играет фрагмент примерно на сорок секунд, после чего плеер сообщает
  `Ended`.
- **Перемешивание и повтор.** Яндекс Музыка не отдаёт Windows управление этими
  режимами: SMTC сообщает `IsShuffleEnabled` и `IsRepeatEnabled` равными `false`,
  а режим повтора приходит пустым. Кнопка, которая заведомо ничего не может
  сделать, хуже отсутствующей, поэтому обе прячутся для плееров, которые их не
  поддерживают, и появляются там, где управление есть (браузер, Spotify).
- **Запуск плеера.** Windows отдаёт медиасессию только пока плеер работает, так
  что после перезагрузки управлять нечем. Виджет сам находит установленное
  приложение (обработчик протокола `yandexmusic://`, запись в «Установка и
  удаление программ», папка по умолчанию) и запускает его свёрнутым через
  6 секунд после старта — если оно ещё не запущено. Отключается в меню «⋯».
- **YouTube.** Панель отдаётся не из `file://`, а с локального адреса
  `http://127.0.0.1:<случайный порт>` ([src/main/server.js](src/main/server.js)).
  Причина: у страницы из `file://` нулевой источник, и встроенный плеер YouTube
  для такой страницы отказывается работать — вместо видео приходит «Видео
  недоступно». С локального адреса источник настоящий, и плеер запускается
  штатно. Сервер слушает только петлевой интерфейс и отдаёт исключительно файлы
  из папки `renderer`.

  Поиск ([src/main/youtube.js](src/main/youtube.js)) не требует ключа API: страница
  выдачи отдаёт свои же данные JSON-блоком в теге `<script>`, его и разбираем.
  Управление плеером — через штатный postMessage-протокол iframe API; поверх
  видео лежит прозрачный слой, поэтому клик по картинке открывает ролик в
  браузере, а пуск, пауза и остановка живут рядом в панели.

  Когда шторка закрыта, панель просто уезжает за край окна — плеер продолжает
  играть, и остаётся звук. Поэтому вкладки переключаются видимостью, а не
  `display: none`: скрытая таким образом вкладка перестала бы воспроизводить.
- **Буфер обмена.** Текст и картинки — опрос системного буфера раз в 450 мс,
  дедупликация по SHA-1. Картинки лежат PNG-файлами в папке данных, в индексе —
  только миниатюра.
- **Файлы в буфере.** Windows кладёт скопированные файлы в формате `CF_HDROP`,
  который Electron не читает: он показывает лишь формат `text/uri-list` и первый
  путь, поэтому два разных набора с одинаковым первым файлом отличить нельзя.
  Слежение вынесено в PowerShell ([src/ps/clip-files.ps1](src/ps/clip-files.ps1)):
  он опрашивает `GetClipboardSequenceNumber` — счётчик, который меняется при
  каждой записи в буфер и, в отличие от чтения содержимого, не открывает буфер и
  никому не мешает копировать. Возврат файлов в буфер идёт через тот же скрипт с
  повтором при занятом буфере.
- **Данные.** `%APPDATA%\vidget\` — `settings.json`, `clipboard.json`,
  `notes.json`, `images\`. Ничего никуда не отправляется.

## Запуск из исходников

```bash
npm install
npm start        # npm run dev — с DevTools
```

`npm start` идёт через [tools/start.js](tools/start.js): он снимает
`ELECTRON_RUN_AS_NODE`, которую выставляет встроенный терминал VS Code — иначе
Electron стартует как обычный Node и падает.

## Установка

```bash
npm run dist        # соберёт dist\Vidget Setup 0.1.0.exe
```

Запустите установщик двойным кликом. Прав администратора он не просит — ставится
в профиль пользователя (`%LOCALAPPDATA%\Programs\Vidget`), папку можно выбрать
свою. В конце оставьте галочку «Запустить Vidget» — виджет сразу появится
полоской у верхней кромки экрана и значком в трее.

Дальше он поднимается сам при каждом входе в Windows. Удаляется как обычная
программа: Параметры → Приложения → Vidget.

Запустить вручную можно из меню «Пуск» → **Vidget**, с ярлыка на рабочем столе
или из `%LOCALAPPDATA%\Programs\Vidget\Vidget.exe`.

## Сборка

```bash
npm run dist            # dist\Vidget Setup 0.1.0.exe — установщик NSIS
npm run dist:portable   # dist\win-unpacked\ — папка без установки
```

Скрипт PowerShell распаковывается из asar (`asarUnpack`) — иначе его нельзя
запустить.

Перед сборкой установщика автоматически отрабатывает
[tools/prepare-signtool.js](tools/prepare-signtool.js). Без него electron-builder
падает с `Cannot create symbolic link`: он распаковывает свой набор для подписи,
внутри которого лежат macOS-симлинки, а создание симлинка в Windows требует
привилегии, которой у обычной учётной записи нет. Скрипт раскладывает тот же
архив сам, пропуская ненужные для Windows файлы, — поэтому режим разработчика и
запуск от администратора не нужны.

## Управление

| Действие | Как |
|---|---|
| Открыть | потянуть полоску вниз, кликнуть по ней, или `Ctrl+Alt+Space` |
| Закрыть | нажать на синий язычок сверху, `Esc`, или клик вне панели |
| Вкладки | `Ctrl+1`…`Ctrl+4` — по порядку слева направо |
| Порядок вкладок | перетащите вкладку мышью на нужное место |
| Громкость | колесо мыши над динамиком или ползунком; клик по динамику — без звука |
| Поиск во вкладке | `Ctrl+F` |
| Меню и выход | «⋯» справа в шапке или значок в трее |

Если `Ctrl+Alt+Space` уже занят другой программой, приложение само возьмёт
первую свободную комбинацию из `Ctrl+Shift+Space`, `Ctrl+Alt+Q`, `Alt+Shift+V`
и запомнит её в `settings.json`.

## Порядок вкладок

Вкладки переставляются перетаскиванием: соседи расступаются по ходу движения,
порядок запоминается в `settings.json` и восстанавливается при следующем запуске.
Клавиши `Ctrl+1`…`Ctrl+4` считают вкладки слева направо, то есть следуют за тем,
что вы видите, а не за порядком в разметке.

Клик и перетаскивание различаются порогом в 4 пикселя, поэтому обычное
переключение вкладки мышью работает как раньше. Ширина у вкладок разная, так что
целевое место считается по серединам соседей, а не делением на равные доли.

## Лайки: подключение аккаунта

Лайкам нужен OAuth-токен вашего аккаунта — он даёт доступ к вашей библиотеке.
Один раз: «⋯» → «Яндекс Музыка» → «Открыть страницу входа», войти, скопировать
из адресной строки значение `access_token` (можно вставить и весь URL целиком —
виджет сам вытащит токен) и нажать «Подключить».

Токен шифруется через `safeStorage` (DPAPI) и лежит в `settings.json` в
зашифрованном виде. Отключить аккаунт можно там же — токен стирается.

Пока аккаунт не подключён, сердечко и дизлайк приглушены, а клик по ним
открывает это окно.

## Автозапуск и восстановление после перезагрузки

Виджет прописывается в автозапуск (`com.vidget.overlay` в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, флаг `--hidden`) и после
входа в систему сам поднимает всё остальное:

- **плеер** — запускается свёрнутым, если не запущен, иначе управлять было бы
  нечем: медиасессии без работающего приложения не существует;
- **аккаунт Яндекса** — вход по сохранённому токену с повторами (1 с, 6 с, 20 с,
  60 с, 3 мин). Один запрос при старте не годится: сеть после загрузки обычно
  ещё не поднялась. Повторы прекращаются, если Яндекс ответил, что токен
  недействителен — тогда нужен новый.

Оба пункта переключаются в меню «⋯» и в контекстном меню трея.

Приложение всегда в одном экземпляре: имя и папка данных заданы явно
(`app.setName` + `app.setPath('userData', …)`), иначе сборка из исходников
(`vidget`) и установленная (`Vidget`) считались бы разными приложениями,
запускались одновременно и затирали хранилище друг друга.

## Если приложение молча закрывается при запуске

Значит, в окружении выставлена `ELECTRON_RUN_AS_NODE=1` (её экспортирует
встроенный терминал VS Code). Electron стартует как обычный Node и завершается,
не показав ошибки. Запускайте из обычного терминала или снимите переменную:
`Remove-Item Env:ELECTRON_RUN_AS_NODE`. Фатальные ошибки самого приложения
пишутся в `%TEMP%\vidget-crash.log`.

## Известные ограничения

- **Обложка альбома** приходит из API Яндекса, то есть только при подключённом
  аккаунте. Без него показывается заглушка с первой буквой названия — кроме
  плееров, которые отдают миниатюру сами (Spotify, браузеры).
- **Поиск YouTube** держится на разметке страницы выдачи. Если YouTube её
  поменяет, поиск начнёт отвечать «не удалось разобрать выдачу» — чинится
  правкой одного разбора в [src/main/youtube.js](src/main/youtube.js).
- **Встраивание некоторых роликов запрещено** их владельцами — плеер покажет
  «Видео недоступно». Кнопка «В браузере» работает всегда.
- **Закреплённые записи** помечены звездой в углу карточки: строка действий
  появляется только при наведении, поэтому состояние нужно было показать отдельно.
- **Файлы в истории** хранятся путями, а не копиями. Если файл переместили или
  удалили, в карточке он показан зачёркнутым и в буфер не вернётся.
- **Аппаратное ускорение выключено** (`app.disableHardwareAcceleration()`):
  на прозрачных always-on-top окнах драйверы Windows 11 рисуют крупные заливки
  лишь частично. Для окна такого размера это не имеет заметной цены.
- Пока шторка закрыта, полоска перехватывает клики в своей зоне (≈260×30 px по
  центру верхнего края).
